# 検証範囲と実機での確認

## PCで行う検証

リポジトリのルートで実行します。CPython 3.10以降、標準ライブラリのみで実行できます。

```sh
python -m unittest discover -s tests -v
python -m compileall -q main.py settings.py presets.py ir_timing.py ir_tx.py read.py send.py wifi.py http_server.py tools
```

テスト対象:

- 途中で分割されたHTTP入力、サイズ制限、期限、Content-Length、不完全な要求。
- 認証なし、GET、未知のID、不正なJSON形式では送信されないこと。
- 送信頻度の制限、送信失敗を成功と表示しないこと。
- 学習中の失敗・記録の置換失敗で以前のデータを壊さないこと。
- 100エッジを超える長い信号、フレーム間40 msの空白、時計のwrap、受信overflow。
- **実際の `ir_tx.py` のPIO命令列**を小さなホスト上のモデルで実行し、搬送波の1/3 duty、複数フレーム、各mark/space長、終端LOWを確認。

PIOモデルはFIFOへの供給遅れや電気特性を再現しません。ソフトウェアテストだけでは、実機のタイミング・赤外線到達距離・対象機種への適合を証明できません。

今回の開発時には32件のホストテスト（実TCP/HTTP経由のAPI操作を含む。送受信ハードウェアは模擬）、JavaScript構文検査、MicroPython v1.26.0公式アセンブラーによるPIO命令のアセンブルを確認しました。ブラウザ本体のダウンロードが失敗したため、ブラウザ上の描画・クリック操作は未検証です。

## Pico Wへ書き込んだ後

`tools/deploy.py` はコピー後に `tools/device_check.py` を実機上で実行します。この検査は設定・モジュールのimport・PIOアセンブル・保存済みデータを確認します。**検査中は赤外線を送信しません。** 実機が接続されていない開発環境では、この検査を実行済みとは扱いません。

## 受け入れ確認

1. 電源投入直後に赤外線LEDが連続点灯しない。受信モジュールの待機出力はHIGH。
2. 正しいキーでログインでき、誤ったキーでは操作できない。
3. 同じリモコン設定を2回、別IDで学習する。パルス数が一致し、波形長がほぼ一致する。大幅に違う場合は、距離・ノイズ・欠落・フレーム間隔を確認する。
4. 「停止」を学習・再送し、エアコンが停止することを確認する。
5. 「冷房26℃・風量自動」などを学習し、エアコンを別設定に変更してから再送する。電源だけでなく、モード・温度・風量・風向も確認する。
6. 同じプリセットを時間を空けて2回送っても、電源トグルにならないことを確認する。トグル式しかない機種では、現在の電源状態を推測して運転・停止を区別しない。
7. 保存後に電源を抜き差ししても、学習内容が残る。再起動だけで赤外線は送られない。
8. Wi-Fiを一時停止・復旧させ、再接続後に操作できる。復旧だけで赤外線は送られない。
9. 最大サイズの学習信号を実機で扱い、メモリ不足やPIO FIFO供給遅れがないか確認する。
10. VPN接続したスマホのモバイル回線から操作し、実際のエアコンの動作をその場の人に確認してもらう。

オシロスコープ/ロジックアナライザーがある場合は、送信GPIOの搬送波周波数と波形を元信号と比較します。PIOの量子化誤差の目安は、markが搬送波周期の半分以下、spaceがPIOクロック周期の半分以下です（FIFOが途切れない場合）。

## 現時点の限界

- リモコンは提供写真でDAIKIN ARC478A65と確認。送受信回路は参考サイトと同じとの申告です。エアコン本体の型番・配線の実測・実機信号は未確認のため、実機対応は未確認です。[回路の確認・修正](ekit-hardware.md)を先に行ってください。
- デフォルト38 kHzは仮定です。復調済み受信信号から搬送波周波数は取得できません。
- キャプチャはデジタル入力のhard IRQです。激しい割り込み競合・ノイズによる取りこぼしは、別途実機で評価が必要です。
- 1回の操作を120 msの無信号で区切ります。内部フレーム間隔がこれ以上の機種は `CAPTURE_IDLE_MS` を調整してください。2秒/2047パルスを超える形式は拒否します。
- リモコンの状態全体を保存するため、未学習の任意温度・風量への変換はしません。トグルビット、ローリングコード、RF/Bluetooth専用リモコンは、この方式では対応できない場合があります。
- サーバーは1リクエストずつ処理します。学習中（最大設定30秒）と送信中は他の操作を待たせます。
- MQTT受信や従来の照明コマンドは新しい `main.py` では実行しません。従来コードは `legacy/` に保存しています。
