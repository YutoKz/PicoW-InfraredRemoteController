# 外出先から操作する

この構成では、Pico Wは自宅LAN内のHTTPサーバーです。外出先のスマホをVPNで自宅LANへ接続し、自宅と同じURLを開きます。Pico W単体にTailscaleをインストールする構成ではありません。

## 用意するもの

- 常時給電するPico Wと赤外線送信回路。
- Pico Wがつながる2.4 GHz Wi-Fi。
- 自宅に常時稼働するLinux端末（Raspberry Pi、Ubuntu PCなど）。Tailscaleのサブネットルーターとして使用します。VPN機能を備えた自宅ルーターがある場合は、そのVPNを使う方法でも構いません。
- スマホのTailscaleアプリ。Linux端末と同じTailscaleネットワークへ参加させます。

## Tailscaleの例

1. 先に自宅Wi-Fiから操作画面を開き、学習・送信・停止が正常にできることを確認します。
2. 自宅ルーターでPico WのDHCP予約を設定します。以下はPico WのIPを **192.168.3.50** とした例です。自分のIPへ置き換えてください。
3. [Tailscale公式のインストール手順](https://tailscale.com/download/linux)に従い、自宅Linux端末を接続します。
4. 自宅Linux端末でIPv4の転送を有効化します。

   ```sh
   echo 'net.ipv4.ip_forward = 1' | sudo tee /etc/sysctl.d/99-picow-forwarding.conf
   sudo sysctl -p /etc/sysctl.d/99-picow-forwarding.conf
   ```

5. Pico Wだけへの経路を広告します。既存の広告ルートがある場合は、そのルートもカンマ区切りで併記してください。

   ```sh
   sudo tailscale set --advertise-routes=192.168.3.50/32
   ```

6. Tailscale管理画面で、そのLinux端末の広告ルートを承認します。アクセス制御を使っている場合は、自分のスマホから `192.168.3.50:80` へのアクセスを許可してください。Linux端末のファイアウォールも転送を許可する必要があります。詳細は[サブネットルーターの公式手順](https://tailscale.com/kb/1019/subnets)を参照してください。
7. スマホのWi-Fiを切ってモバイル回線へ切り替え、Tailscaleを接続し、`http://192.168.3.50/` を開きます。設定したアクセスキーを入力します。

自宅Linux端末のスリープ・電源断中は外出先からアクセスできません。通常のPico Wへの通信先はTailscale端末の100.xのIPではなく、上記のPico WのLAN内IPです。

## 接続の扱い

- ルーターでHTTPポートをインターネットへ公開しないでください。公開用Webサーバーとしては設計していません。
- VPNの暗号化はスマホからサブネットルーターまでです。サブネットルーターからPico WまではHTTPなので、信頼できる自宅LANを使用してください。
- Wi-Fiのゲスト分離/AP分離が有効なネットワークでは、Pico Wへ届かないことがあります。
- アクセスキーはURLに入れません。ブラウザのメモリで保持し、ページを閉じると失われます。
- 送信後の画面表示は、赤外線を出したという意味です。エアコンからの返答は受信しないため、運転状態の確認にはなりません。

## 初回の外出テスト

在宅者がエアコンを確認できる状態で、スマホをモバイル回線に切り替え、「停止」「冷房のプリセット」「停止」の順で確認してください。Pico Wを再起動したときやWi-Fiが復旧したときに、登録済み操作が勝手に送信されないことも確認します。
