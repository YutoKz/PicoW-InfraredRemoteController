# 参考サイトと同じ回路で始める

2026-10-20時点の確認事項です。ユーザーの写真からリモコンは **DAIKIN ARC478A65** と確認しました。送受信回路は、リポジトリの参考リンクである[マイコン技術Naviの記事](https://www.ekit-tech.com/?p=2535)と同じとの申告に基づきます。実物の配線、エアコン本体型番、赤外線波形はまだ未確認です。別のサイトを指していた場合は、この配線を適用せずURLを確認してください。

## 配線とコードの対応

記事の[受信回路図](https://www.ekit-tech.com/wp-content/uploads/20211001-13-1200x675.jpg)・[送信回路図](https://www.ekit-tech.com/wp-content/uploads/20211001-14-1200x675.jpg)を確認しました。

| 部分 | 記事の部品・配線 | 今回の設定 |
| --- | --- | --- |
| 受信 | OSRB38C9AAのOUT → GP26（物理31番） | `IR_RECEIVE_PIN = 26` |
| 受信電源 | VCC → 3V3(OUT)（物理36番）、GND → 物理38番 | 3.3 Vのactive-lowデジタル入力 |
| 送信 | OSI5FU5111C-40のアノード → GP17（物理22番）、カソード → GND | `IR_SEND_PIN = 17`、HIGHで発光 |
| 搬送波 | 記事は38 kHz | `IR_CARRIER_HZ = 38000`。ARC478A65での実測値ではない |

GPIO番号はデフォルト設定のままで一致します。記事の基板は通常のPicoですが、今回のWi-Fi用コードには **Pico W / WH** が必要です。

## 送信回路には抵抗を追加する

記事の送信回路図は、LEDをGPIOとGNDの間へ直接接続しており、電流制限抵抗が描かれていません。**図のままの直結では送信試験を行わず、電源を外してから直列抵抗を追加してください。** PWMのデューティ比を下げても、点灯中の電流制限にはなりません。

近距離での初期確認は、GP17 → **1 kΩの抵抗（例: 1/4 W）** → LEDのアノード、LEDのカソード → GNDとします。3.3 V / 1 kΩから、LEDの電圧降下を無視しても電流は約3.3 mA以下となる計算です。これは弱い出力での確認用であり、部屋の中で届く距離を保証しません。

記事の筆者が報告した到達距離は約30 cmで、今回の回路・エアコンでの測定結果ではありません。常設で離れたエアコンまで届かせる場合は、LEDの仕様に合わせた電流制限抵抗とトランジスター等の駆動段を設けます。GPIOから流す電流を増やすために抵抗を取り除かないでください。

## 受信は仕様上デジタル入力で扱える

[OptoSupplyのOSRB38C9AAデータシート](https://akizukidenshi.com/goodsaffix/OSRB38C9AA.pdf)では、電源範囲2.7～5.5 V、中心周波数37.9 kHz、active-low出力です。3 V給電時のHIGH出力は最低2.7 Vとされています。今回の3.3 V給電・デジタル割り込みによる受信に合う仕様です。5 V給電には変更しないでください。

一方、記事本文には待機出力が約1.5 VだったためADCを使ったと記載されています。これは上記仕様と異なるため、同じ値になると仮定したり、必ず正常にHIGHになると断定したりはできません。

学習前に、リモコンを押していない状態でOUTとGNDの間の電圧が3.3 V付近であるか確認してください。実測でも約1.5 Vの場合は、電源・ピンの向き・配線・部品を確認し、その値を共有してください。`Receiver must be idle HIGH` が出たときも同様です。コードの確認処理を削除して学習を続けないでください。

## 次の実機確認

1. 基板がPico W / WHであること、送信LEDの直列抵抗、受信部の3.3 V給電を確認する。
2. READMEの手順で設定とコードを書き込み、スマホから操作画面へ接続する。
3. 元リモコンの「停止」を `off` として学習する。次に「冷房26℃・風量自動」「送風」など、使用したい設定をそれぞれ学習する。
4. LEDをエアコン受光部へ近づけて再送し、その場で動作を確認する。反応がなければ距離・向き・波形・搬送波の順に切り分ける。
5. LAN内で動作してから、READMEのVPN接続手順へ進む。

ARC478A65という型番だけから機種固有の通信形式や任意温度の生成方式は確定していません。現段階では元のリモコンから得た信号を再送する方式を使い、対応済みとは扱いません。
